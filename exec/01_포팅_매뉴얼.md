## 1. 시스템 구성

단일 EC2 한 대에 Docker Compose로 6개 컨테이너를 띄웁니다. 외부에 공개되는 포트는 Nginx의 80/443뿐입니다.

```
[브라우저] ──HTTPS──▶ Nginx (정적 SPA 서빙 + /api 리버스 프록시, TLS 종료)
                        │  (도커 내부 네트워크 gongguhan-net)
                        ├──▶ backend  : Spring Boot  :8080  (/api/v1)
                        │       ├──▶ mysql : MySQL 8.0 :3306
                        │       ├──▶ redis : Redis 7   :6379
                        │       └──▶ ai    : FastAPI   :8000
                        └── certbot (인증서 자동 갱신)
```

| 서비스 | 소스 폴더 | Dockerfile |
|---|---|---|
| frontend + Nginx | `frontend/` | `deploy/frontend.Dockerfile` |
| backend | `backend/` | `deploy/backend.Dockerfile` |
| ai | `ai/` | `deploy/ai.Dockerfile` |
| mysql / redis / certbot | 공식 이미지 | – |

설계 배경: `docs/infra/서버_아키텍처_설계서.md`

## 3. 로컬 개발 환경 실행

```bash
git clone <GitLab 저장소 URL> S15P21B205
cd S15P21B205

# 1) 인프라 (MySQL 3306, Redis 6379, MinIO 9000/9001)
docker compose up -d
#   로컬에 이미 MySQL이 3306을 쓰면 docker-compose.override.yml 로 3307 노출 후
#   backend/.env 의 DB_URL 포트도 3307 로 맞춘다.

# 2) Backend (http://localhost:8080/api/v1, Swagger: /api/v1/swagger-ui/index.html)
cd backend
cp .env.example .env          # 값 채우기 (4장 참고). bootRun 시 .env 자동 로드
./gradlew bootRun             # 기본 프로파일 local, Flyway가 스키마 자동 생성

# 3) AI 서버 (http://localhost:8000)
cd ../ai
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app:app --host 0.0.0.0 --port 8000

# 4) Frontend (http://localhost:5173)
cd ../frontend
cp .env.example .env
npm ci
npm run dev
```

## 5. 운영 배포 절차 (EC2)

```bash
# 1) 접속
ssh -i J15B205T.pem ubuntu@j15b205.p.ssafy.io

# 2) Docker 설치 (최초 1회)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ubuntu        # 재로그인

# 3) 소스
git clone <GitLab 저장소 URL> S15P21B205 && cd S15P21B205
git checkout DevelopV2                 # 현재 운영 브랜치 (master와 동일 커밋)

# 4) 방화벽 (22/80/443만 개방)
cd deploy && chmod +x scripts/ufw-setup.sh && sudo ./scripts/ufw-setup.sh

# 5) 환경변수 / 시크릿
cp env/backend.env.example env/backend.env
cp env/mysql.env.example   env/mysql.env
cp env/ai.env.example      env/ai.env
mkdir -p secrets && mv ~/gcp-sa.json secrets/gcp-sa.json
chmod 644 secrets/gcp-sa.json          # AI 컨테이너(비-root)가 읽을 수 있어야 함

# 6) TLS 인증서 발급 (최초 1회)
docker compose -f docker-compose.prod.yml run --rm certbot certonly \
  --webroot -w /var/www/certbot -d j15b205.p.ssafy.io --agree-tos -m <이메일>

# 7) 빌드 & 기동
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps

# 8) 코인 결제 설정 시드 (최초 1회)
docker compose -f docker-compose.prod.yml exec -T mysql \
  mysql -u<USER> -p<PASSWORD> gongguhan < ../backend/scripts/seed-crypto-config.sql

# 9) 확인
curl https://j15b205.p.ssafy.io/api/v1/actuator/health     # {"status":"UP"}
```

자주 쓰는 명령:

```bash
docker compose -f docker-compose.prod.yml logs -f backend
docker compose -f docker-compose.prod.yml up -d --build backend   # 백엔드만 재배포
docker compose -f docker-compose.prod.yml down                     # 정지 (볼륨 유지)
```

### 5-1. Jenkins CI/CD (현재 운영 배포 방식)

위 5장은 최초 구축과 수동 배포 절차입니다. 현재는 같은 EC2에 띄운 **Jenkins**가 테스트 → 이미지 빌드 → 배포를 자동으로 수행합니다.

| 항목 | 내용 |
|---|---|
| Jenkins | `jenkins/jenkins:lts-jdk21` (controller) + 전용 agent 컨테이너 (`deploy/jenkins/compose.yml`, 프로젝트명 `gongguhan-ci`) |
| 접속 | `127.0.0.1:8088` 바인딩만 존재해 외부 비공개 → SSH 터널로 접속 (`ssh -L 8088:127.0.0.1:8088 ...`) |
| 파이프라인 | 루트 `Jenkinsfile` |
| 배포 Job | `gongguhan-DevelopV2` (origin/DevelopV2 기준), 검증 Job `gongguhan-ci-validation` |
| GitLab 인증 | 읽기 전용 토큰 `/opt/gongguhan-ci/secrets/gitlab-read.json` → Jenkins credential `gongguhan-gitlab-read` |
| 호스트 준비 | `deploy/jenkins/setup-host.sh` (`/opt/gongguhan-ci/{workspace,releases,state,secrets}` 생성) |

파이프라인 단계:

1. **Checkout** — 배포 Job은 `origin/DevelopV2`가 아니면 실패 처리
2. **Frontend test and build** — `deploy/jenkins/ci.sh frontend`
3. **Deployment guards** — `deploy/jenkins/test_*.py` (Flyway 마이그레이션 검증 등)
4. **Backend regression** — Gradle 테스트, JUnit 리포트 수집
5. **AI regression** — pytest, JUnit 리포트 수집
6. **Build release images** — 커밋 SHA 태그 이미지(`gongguhan-ci/{backend,ai,nginx}:<SHA>`) 빌드
7. **Deploy DevelopV2** — `deploy/jenkins/deploy.py <SHA>`: 테스트를 통과한 불변 이미지로 교체하고, 헬스체크에 실패하면 직전 이미지로 롤백 (DB는 롤백하지 않음)

Jenkins 기동:

```bash
# 사전: GitLab 읽기 전용 토큰을 /opt/gongguhan-ci/secrets/gitlab-read.json 에 배치
#       (운영 스택 gongguhan-prod 가 먼저 떠 있어야 함 — 롤백 기준 이미지를 기록)
cd ~/S15P21B205/deploy/jenkins
./setup-host.sh          # 디렉터리·관리자 비밀번호(/opt/gongguhan-ci/secrets/admin-password)·롤백 기준 생성
DOCKER_GID=$(stat -c %g /var/run/docker.sock) docker compose -f compose.yml up -d --build
```

## 6. 배포 시 특이사항

1. **내부 포트는 호스트에 노출하지 않습니다.** Docker는 iptables를 직접 수정해 UFW 규칙을 우회합니다. 그래서 backend/ai/mysql/redis에는 `ports:`를 두지 않고, 서비스 이름으로만 내부 통신합니다.
2. **백엔드 컨테이너는 반드시 KST입니다.** (`TZ=Asia/Seoul`, `-Duser.timezone=Asia/Seoul`) SSAFY 금융망은 전송 시각을 KST로 검증하므로 UTC이면 `H1003` 오류로 거부됩니다.
3. **스키마는 Flyway가 기동 시 자동 적용합니다** (V1~V22, JPA `ddl-auto`는 validate). DB를 수동으로 만들 필요가 없습니다.
4. **코인 결제 주소는 시드 스크립트로 넣습니다.** 마이그레이션에는 컨트랙트·지갑 주소가 `0x000…0`으로 들어 있습니다. `seed-crypto-config.sql`을 빼먹어도 서버는 뜨지만, 결제 단계에서 "수취 지갑 주소가 아직 설정되지 않았습니다"가 뜹니다. 환불 지갑에는 가스비용 POL과 USDT가 있어야 합니다.
5. **SSAFY 금융망 가맹점 ID**는 V7 마이그레이션이 `platform_policies`에 시드합니다. 재등록은 `backend/scripts/ssafy-create-merchant.mjs`를 씁니다.
6. **prod 프로파일은 Swagger를 비활성화**하고, Redis 슬롯 게이트의 로컬 폴백을 끕니다.
7. **업로드 한도**: Nginx `client_max_body_size 30m` = 백엔드 multipart 최대 30MB.
8. **SPA 라우팅**: Nginx `try_files $uri /index.html` 폴백. 가상 은행 조회 콘솔은 `https://j15b205.p.ssafy.io/bank-console.html`에서 열립니다.
9. **배치 스케줄러**(슬롯 만료 1분, 코인 컨펌 5초, 환불 복구 1분, 정산 매일 03:00)는 ShedLock이 없어 **인스턴스 1대 운영을 전제**로 합니다.
