# 공동구매 생성에서 상품 등록으로 이동하는 흐름

이슈: S15P21B205-183. 기준: DevelopV2 1a4b9c6. 작성일: 2026-09-21.

## 증상과 원인

판매자 홈의 공동구매 생성하기는 `/seller/group-buys/new`로 이동한다. 이 화면은 등록된 상품에서 공구 미연결 상품을 골라 모집 조건을 설정하는 두 번째 단계다. 상단에는 `1. 상품 등록 / 2. 공동구매 생성`이 표시되지만 Steps는 텍스트만 렌더링하므로 첫 번째 단계로 이동할 수 없었다. 상품이 하나도 없거나 모든 상품이 공구에 연결되어 있으면 안내문만 나오고 상품 등록 화면에 갈 수 있는 링크가 없었다.

반대로 상품 등록 화면은 이미 정상적인 다음 단계 연결을 가지고 있었다. 상품 생성 성공 후 판매자 상품 쿼리를 무효화하고 서버가 반환한 product.id를 `/seller/group-buys/new?productId=...`에 전달한다. 따라서 빠져 있던 것은 등록 후 연결이 아니라 등록 전 진입이었다. AI 이미지 분석을 포함한 상품 등록 내부를 다시 구현할 필요는 없다.

## 선택과 제외한 대안

홈 버튼을 무조건 상품 등록으로 바꾸면 이미 등록한 상품으로 공구를 열려는 사용자가 불필요한 첫 단계를 거쳐야 한다. 현재 상품 선택 화면은 유지하고 세 곳에 명확한 등록 진입점을 추가했다. 상단의 새 상품 등록, 진행 단계의 상품 등록 링크, 선택 가능한 상품이 없는 경우의 상품 등록하기 버튼이다.

빈 목록을 보고 자동으로 이동시키는 방법도 가능하지만 목록 조회 장애와 실제 빈 목록을 혼동하면 원인을 숨길 수 있다. 또한 사용자가 무슨 일이 일어났는지 보기 전에 페이지가 전환된다. 현재의 오류·로딩·빈 목록 안내는 유지하고 사용자가 링크를 선택하도록 했다.

## 구현의 책임

SellerGroupBuyNewPage는 기존 ButtonLink를 재사용한다. 이동이 목적이므로 submit 버튼이 아닌 링크이며 생성 API를 호출하지 않는다. 기존 공구 생성 폼, 가격 미리보기, 상품 필터는 수정하지 않았다. 스타일 파일도 변경하지 않았다.

공용 Steps에는 선택적인 links 배열만 추가한다. 목적지를 전달한 단계만 React Router Link로 렌더링하고 전달하지 않은 결제 등 기존 화면은 텍스트 표시를 유지한다. 현재 단계를 표시하는 aria-current도 그대로다. 공용 컴포넌트를 변경할 때 모든 화면을 클릭 가능하게 바꾸지 않도록 opt-in으로 설계한 이유다.

상품을 새로 등록하려고 화면을 떠나면 아직 제출하지 않은 모집 조건은 보존하지 않는다. 이 변경은 공구 초안 저장 기능을 추가한 것이 아니며 서버 데이터는 변경하지 않는다. 등록 화면에서 돌아온 productId의 자동 선택 계약은 회귀 테스트로 유지되는지 확인한다.

## 수정 전·후 검증

실제 페이지를 QueryClientProvider와 MemoryRouter 안에서 서버 렌더링하는 테스트 5개를 먼저 추가했다. 상품이 없는 경우, 상품이 있는 경우, 등록 직후 productId 지정, 모든 상품이 이미 공구에 연결된 경우, 링크를 전달하지 않은 기존 Steps 동작을 검사한다. 수정 전에는 3개 실패·2개 통과였다. 실패 3개는 정확히 누락된 상품 등록 진입 링크였고 나머지는 보존해야 할 기존 동작이었다.

수정 후 프런트 전체 102개 테스트가 통과했다(기준 97개 + 새 테스트 5개). 기존 Vitest 설정은 `.test.ts`만 찾았으므로 컴포넌트 `.test.tsx`도 검색하도록 범위를 확장했다. DOM 라이브러리를 새로 추가하지 않고 기존 react-dom/server를 사용했다. 타입 검사는 테스트 데이터의 페이지 메타 구조 오류도 발견했고 실제 Paged 계약인 `{items, meta}`로 바로잡았다.

타입 검사·ESLint·프로덕션 빌드로 경로 및 공통 컴포넌트 사용을 함께 검사한다. 서버 렌더링 테스트는 링크 목적지와 화면 분기를 확인하지만 실제 로그인, 이미지 업로드, 상품 생성 API까지의 E2E는 아니다. 따라서 이번 결과를 S3 업로드나 AI 이미지 추출 실환경 성공의 증거로 사용하지 않는다. 외부 Docker 테스트는 사용자 요청으로 보류했다.

## 재검토 및 학습 순서

SellerHomePage의 진입 경로, SellerGroupBuyNewPage의 조회·빈 목록 분기, Steps의 opt-in 링크, SellerProductNewPage의 생성 성공 후 이동 순서로 읽으면 전체 흐름을 이해할 수 있다. 테스트 파일은 `frontend/src/pages/seller/SellerGroupBuyNewPage.test.tsx`다. frontend에서 `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`로 재실행한다.

성능 최적화가 아닌 길찾기 기능 수정이다. 처리속도 개선을 주장하지 않으며 테스트 통과 개수는 성능 지표가 아니다. DevelopV2로만 MR을 생성하고 병합하며 DevelopV1과 배포 서버는 변경하지 않는다.
