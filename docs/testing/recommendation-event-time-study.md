# 추천 이벤트의 기준 시각 일관성

이슈 S15P21B205-193. 기준 DevelopV2 6074d5e. AI 추천 로직의 미래 이벤트 반영만 수정한다.

## 발견한 오류와 재현 조건

build_user_profile의 설명은 현재 이전 행동으로 선호를 계산한다고 했지만 실제 구현은 나이를 계산한 뒤 음수를 0으로 잘랐다. 미래 행동의 나이가 0이 되면 가장 최근의 강한 행동으로 인정된다. recommend 또한 모든 이벤트를 train_model에 넘기고 최근 30일 구매 감점에서 하한만 비교했다. 그 결과 내일 구매한 기록이 지금의 브랜드 선호, 학습 모델 선택, 재구매 억제 점수에 모두 영향을 주었다.

실서비스 이벤트 시각은 서버가 기록하므로 정상 환경에서 빈번한 사용자 조작 입력은 아니다. 하지만 명시적인 now로 과거를 재현하는 평가나 시계가 어긋난 데이터에서는 실제로 결과가 달라진다. 미래 정보를 사용한 점수가 과거 시점의 추천 결과인 것처럼 취급되면 테스트/모델 비교도 신뢰할 수 없다.

## 대안과 선택 기준

미래 이벤트를 기준 시각으로 강제 변경하면 아직 관측하지 않은 행동을 관측한 것으로 만들기 때문에 제외했다. 선호도만 고치면 학습과 구매 감점에는 여전히 미래 데이터가 남는다. DB에서만 현재시각 이전을 조회하면 Python 함수의 명시적인 과거 now 재현을 보장하지 못한다. 따라서 추천 요청에서 한 번 정한 now를 기준으로 events를 필터링한 뒤 세 용도 모두 같은 이력을 사용하도록 했다. 독립적으로 공개 사용되는 build_user_profile에서도 동일 경계를 적용한다.

기간 경계는 occurred_at <= now다. 기준 시각에 이미 관측된 이벤트는 사용하고 이후 이벤트만 제외한다. timezone이 있는 값은 UTC로 정규화하고 timezone 없는 입력은 기존 정책대로 UTC로 해석한다. API DTO나 응답 필드를 변경하지 않는다.

## 코드 흐름

recommend에서 now 정규화 후 이벤트 occurred_at을 UTC datetime으로 변환하고 기준 시각 이하의 복사본을 선택한다. 이후 누락된 특징 연결, 선호도 생성, 모델 학습, 최근 구매 감점이 모두 이 제한된 events를 받는다. build_user_profile도 사용자 ID·허용 이벤트 종류·시각 조건을 함께 적용한다. 유효 과거 데이터의 점수 가중치, 14일 감쇠율, 최근 30일 구매 0.05 배율은 변경하지 않는다.

## 전후 검증

새 test_recommendation_time.py는 7개 사례를 구성한다. 미래 구매만 있으면 선호가 비어야 한다. 같은 시각을 UTC/KST/시간대 없는 값으로 표현한 세 사례는 동일하게 포함돼야 한다. 미래 구매가 추가돼도 이벤트가 없는 기준 결과의 전체 DataFrame과 같아야 한다. 미래 양성/음성 이벤트 24개가 있어도 학습 모델로 전환되면 안 된다. 과거 1시간 전의 구매는 기존대로 해당 상품 점수를 낮춰야 한다.

수정 전 7개 중 미래 선호·결과 동일성·학습 배제의 3개가 실패했고 나머지 4개가 통과했다. 수정 후 AI 전체 pytest 15개 통과, 실패 0. FastAPI/Starlette와 NumPy 의존성의 deprecation 경고 7개는 남아 있으며 숨기거나 성공 증거에서 지우지 않았다. 사용한 실행환경은 프로젝트 외부의 기존 .qa-ai-venv Python이다. 백엔드/프런트 소스는 이 MR에서 바꾸지 않았다.

## 성능과 검증 한계

이번 변경은 추천 기준 시점의 정합성 수정이지 성능 개선이 아니다. pytest 전체 시간은 요청 지연이나 모델 정확도 지표가 아니다. 정확도/전환율 향상을 주장하지 않으며 실제 사용자 행동 데이터 평가도 수행하지 않았다. 배포 서버나 운영 이력을 수정하지 않았다.

별개의 데이터 한계가 남는다. 백엔드 findTrainingEvents의 PURCHASE 행은 참여 시각을 가져오지만 모집률·가격 일부를 현재 공동구매/상품에서 읽는다. 실제 구매 시각의 해당 값은 과거 스냅샷이 없으면 복원할 수 없다. 이번 필터는 이 문제를 해결했다고 주장하지 않는다. 정확한 과거 특징이 필요하면 승인 트랜잭션에서 확정 스냅샷을 저장하는 별도 설계와 마이그레이션, 과거 행의 명시적인 누락값 정책이 필요하다. 현재값을 과거값으로 임의 보정하지 않았다.

ai 폴더에서 기존 Python 환경으로 `python -m pytest test_recommendation_time.py -q`, 전체는 `python -m pytest -q`로 재실행한다. 학습 순서는 테스트의 기준 시각 → build_user_profile 조건 → recommend의 events 필터 → 구매 감점 순서가 적합하다. 동일한 now를 여러 후속 계산에 전달하는 이유를 이 순서로 확인할 수 있다.
