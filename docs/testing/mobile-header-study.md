# B10 모바일 헤더 메뉴 잘림과 로고 소실

이슈: S15P21B205-200. DevelopV2 전용. 색·폰트·아이콘·메뉴 구성은 바꾸지 않고 모바일의 내용 수용 방식만 수정했다.

## 원인과 대안

기존 헤더는 모바일에서 높이를 60px로 줄이고 메뉴 간격만 줄였다. 로그인하면 거래관리·내 정보·로그아웃이 늘어나는데 바깥 flex는 줄바꿈하지 않았다. 로고 컨테이너가 0px까지 줄어들고 판매자센터 버튼이 오른쪽을 벗어났다. 390px 점검용 로그인 메뉴 fixture에서 실제 브라우저의 로고 폭 0px와 버튼 잘림을 재현했다. 비로그인 실제 홈도 360px에서 로고 폭이 44.26px로 눌렸다.

overflow-x:hidden으로 넘친 부분을 숨기면 버튼이 사라진 상태를 고치지 못한다. 메뉴를 없애거나 새 햄버거 메뉴를 만드는 것은 현재 디자인을 불필요하게 바꾸므로 제외했다. 620px 이하에서 기존 flex 항목이 필요한 만큼 줄바꿈하고 높이가 내용에 맞게 늘어나도록 했다. 로고는 축소하지 않으며 nav와 right의 min-width를 0으로 명시했다.

## 구현

global.css의 기존 620px media 구역만 바꿨다. inner는 min-height 60px 및 auto height, flex-wrap과 기존 계열 간격을 사용한다. right는 줄바꿈 가능한 300px 기준 flex이고 nav는 220px 기준으로 줄바꿈한다. 텍스트/색상/버튼 토큰은 그대로다. 메뉴를 숨기거나 페이지 전체 스크롤을 억제하는 CSS는 추가하지 않았다.

frontend/qa/header.html은 네트워크 호출·실제 로그인 없이 가장 긴 로그인 메뉴를 검사하는 정적 fixture다. 실제 로고와 공통 CSS를 불러오며 production Vite 기본 빌드에는 포함되지 않는다. 실제 SiteHeader 비로그인 홈도 별도로 확인했다. 이 fixture 검사를 실제 인증 E2E라고 주장하지 않는다.

## 실제 렌더링 측정

브라우저 사용 도구로 임시 viewport를 지정하고 DOM bounding rect 및 scrollWidth를 읽었다. 모든 링크·버튼이 inner 좌우 경계 안에 있는지 검사했다. 측정 후 viewport override를 해제하고 임시 탭을 닫았다.

| viewport | inner 폭 | 헤더 scrollWidth | 로고 폭 | 잘린 메뉴 수 |
|---|---:|---:|---:|---:|
| 360 | 345 | 345 | 64.84 | 0 |
| 375 | 360 | 360 | 64.84 | 0 |
| 390 | 375 | 375 | 64.84 | 0 |
| 414 | 399 | 399 | 64.84 | 0 |
| 620 | 605 | 605 | 64.84 | 0 |
| 1024 | 1000 | 1009 | 79.58 | 0 |

스크롤바 공간을 보존하는 기존 scrollbar-gutter 때문에 viewport와 콘텐츠 폭이 다르다. 1024px의 header는 전체 콘텐츠 너비이고 inner는 max-width 1000px이므로 둘이 다른 것은 overflow 증거가 아니다. 실제 홈 360px에서도 clientWidth=345, scrollWidth=345, 로고 64.84px로 확인했다.

## 검증 한계와 재실행

이 수치는 UI 기하학적 회귀 지표이지 네트워크/처리 성능 개선 지표가 아니다. 서버가 실행되지 않은 로컬 홈의 목록 오류는 헤더 테스트 범위에서 분리했다. 실제 로그인 요청, 금융 처리, 알림 패널 열린 상태, 모든 페이지의 표 폭까지 검증했다는 의미는 아니다. FE 회귀·ESLint·타입 포함 빌드를 별도로 실행했다.

재현은 frontend 개발 서버의 /qa/header.html에서 360·375·390·414·620·1024px로 바꾸고 로고와 각 메뉴 rect를 확인한다. 학습 시 기존 inner의 고정 높이와 flex-shrink 기본값을 먼저 보고 수정 media 규칙을 읽으면 된다.
