# B08 결제 종료를 승인 실패로 단정하지 않기

이슈: S15P21B205-205. 수단 전환·화면 이탈로 abort한 결제는 실제 승인 호출 없이도 FAILED가 된다. 기존 결제 내역은 이를 모두 승인 실패로 표시했다. 서버 상태에 없는 상세 원인을 프런트가 추측하면 잘못된 금융 안내가 되므로 공통 상태 표기를 결제 종료로 바꾸고 여러 종료 원인이 포함될 수 있음을 설명했다.

수단 전환 건을 무조건 사용자 취소로 바꾸는 방법도 제외했다. 실제 승인 거절 역시 같은 enum으로 오므로 새 오표시가 생기기 때문이다. 원장에 종료 사유를 추가하면 더 세밀한 문구를 제공할 수 있지만 과거 거래 원인을 단정하여 역보정할 근거가 없으므로 이번 수정은 확인 가능한 범위만 표현한다. EXPIRED의 시간 만료와 PAID의 결제 완료 표기는 보존했다.

상태표 테스트 2개를 추가하고 전체 프런트 회귀·타입 포함 빌드·ESLint를 실행한다. 이 수정은 데이터 상태를 바꾸거나 환불을 실행하지 않는다. 상세 종료 사유별 표시 구현까지 끝났다는 의미도 아니다. 코드 학습은 entities/model.ts의 상태-문구 매핑과 OrdersPaymentsPage 설명을 함께 읽으면 된다. 성능 개선 대상이 아닌 안내 정확성 수정이므로 처리속도 수치는 주장하지 않는다.
